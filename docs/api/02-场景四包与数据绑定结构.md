# 场景四包与数据绑定结构

日期：2026-10-20。适用接口：详情、整体保存、模板快照另存、发布及发布预览。接口外层见 [业务契约](01-业务接口与后端实施契约.md)。

## 1. 四包职责与解析原则

保存请求的 `sceneJson/threeDJson/twoDJson/dependenciesJson` 都是字符串，分别解析得到下述对象。请求顶层包含 `sceneId`；四包不以旧演示 `scene-core` 的精简模型替代。结构版本当前为 1，后端应显式检验支持范围。

| 包 | 保存内容 | 后端解析程度 |
| --- | --- | --- |
| `sceneJson` | 场景容器、类型、元信息、公共接口、全局请求配置、场景动作 | 校验结构和公共引用；保留扩展 |
| `threeDJson` | 三维基础配置、对象/组件、图层、流式策略、相机路径、植被 | 正常存取保留原文；为校验/索引解析必要字段；不要求后端负责渲染 |
| `twoDJson` | 画布、二维本体、布局样式、外层动画、视觉管理树 | 校验身份/树引用；不执行部件和图表逻辑 |
| `dependenciesJson` | 资源、实例数据绑定、状态/事件行为、设备绑定 | 原文保全并建立拥有者索引，支持按实例取依赖 |

后端保留完整包与单条依赖原文，索引属于派生数据。不能为了生成实体类而丢弃 `contentJson`、扩展字段、未知依赖类型，或把空字符串、缺失和空值随意互换。不要将大整数编号读入浮点数后再写回。

独立二维阶段会编辑二维并保存混合场景；原始三维包原文直通，三维/未知归属依赖按稳定身份保留。后端不能重建一个只认识二维的依赖包覆盖全场景。

## 2. 场景容器包

```json
{
  "schemaVersion":1,
  "name":"设备监控场景",
  "sceneType":"local3d",
  "domainSlots":{"twoD":"present","threeD":"present"},
  "metadata":{},
  "requestGlobalConfig":{"requestOriginUrl":"","requestInterval":null,"requestIntervalUnit":"second","requestParams":{"Header":{}}},
  "publicRequests":[],
  "sceneActions":[]
}
```

| 字段 | 类型/约束 |
| --- | --- |
| `schemaVersion` | 整数，当前 1 |
| `name` | 场景名称字符串 |
| `sceneType` | `local3d/gis`，表示坐标业务语义，不表示渲染引擎 |
| `domainSlots` | 始终声明二维与三维均 `present`，即使对应内容为空 |
| `metadata` | 可扩展普通对象，含业务扩展，原样保留 |
| `requestGlobalConfig` | 全局请求默认值，不属于任何实例 |
| `publicRequests` | 公共接口完整定义数组，按 `publicRequestKey` 关联消费者 |
| `sceneActions` | 无实例拥有者的场景动作数组 |

`sceneId`、租户和发布身份来自接口/主表，不信任正文中的历史身份。`local3d` 使用局部坐标，`gis` 保留地理语义；后续 Unity 接入不能直接将地理场景改成局部场景。

公共接口保存结构：

```json
{
  "publicRequestKey":"public-status",
  "name":"设备状态",
  "requestConfig":{
    "requestHttpType":"GET","requestOriginUrl":"","requestUrl":"/device/status",
    "requestInterval":30,"requestIntervalUnit":"second",
    "requestContentType":"default","requestParamsBodyType":"none",
    "requestParams":{"Params":{},"Header":{},"Body":{"form-data":{},"x-www-form-urlencoded":{},"json":"","xml":""}},
    "requestSQLContent":{"sql":""},"useAuth":false
  }
}
```

公共请求定义恢复不等于立即执行；首次激活消费者才启动共享请求。实例绑定只保存公共编号、自己的提取/映射/过滤，不重复复制公共定义。全局默认值支持请求前置地址、默认间隔及共享请求头，单请求按现有覆盖规则生效。

场景动作结构：`actionKey:string,triggerType:string,enabled:boolean,sortNo:number,targets:Owner[],triggerConfig:对象,actionConfig:对象`。来源给出 `scene-ready` 示例，但没有冻结所有触发枚举；后端不得假设只有一种或执行任意动作脚本。

## 3. 二维内容包

### 3.1 画布与组件

```json
{
  "canvas":{"width":1920,"height":1080},
  "components":[{
    "instanceId":"400001","componentType":"VTextCommon","resourceRefKeys":[],
    "visible":true,"locked":false,"sortNo":0,
    "layoutConfig":{"l":100,"t":100,"w":260,"h":80,"zIndex":0},
    "styleConfig":{"animations":[]},
    "renderConfig":{"value":"设备在线","fontSize":20,"fontColor":"#ffffff"},
    "animationConfig":{"items":[]},
    "contentJson":{"widget":{"id":"400001","component":{
      "info":{"name":"文字","keyName":"VTextCommon","packageName":"Widget"},
      "attr":{"l":100,"t":100,"w":260,"h":80,"zIndex":0},
      "option":{"value":"设备在线","fontSize":20,"fontColor":"#ffffff"},
      "styles":{"animations":[]}
    }}}
  }],
  "layerTree":[{"id":"400001","type":"widget"}]
}
```

此例展示正式字段形态，省略文字组件其余默认选项；前端会用对应配置类补默认值。后端存取时必须保留所有实际传入字段，不能只保留例子中的选项。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `canvas.width/height` | 正数 | 逻辑画布尺寸，布局坐标不使用网页设备像素 |
| `components` | 组件数组 | 包括初始隐藏组件，不能只存可见项 |
| `instanceId` | 非空字符串 | 与前端 `widget.id` 一致；跨二维/三维唯一 |
| `parentInstanceId` | 可选字符串 | 真实组件父级，不能用视觉组编号替代 |
| `componentType` | 字符串 | 注册键名，例如 `VTextCommon/VButton/VBar`；不要用中文显示名称 |
| `resourceRefKeys` | 字符串数组 | 普通市场资源稳定引用；外部直连资源可为空 |
| `visible/locked` | 布尔 | 本体状态，叠加祖先组状态得到最终结果 |
| `sortNo` | 整数 | 保存时实例次序 |
| `layerKey` | 可选字符串 | 所属视觉管理组 |
| `layoutConfig` | 对象 | `l,t,w,h,zIndex` 等布局字段 |
| `styleConfig` | 对象 | 来源组件样式配置及扩展 |
| `renderConfig` | 对象 | 组件自身 `option`，按组件类型不同；图表不能统一成文字对象 |
| `animationConfig` | 对象 | 外层动画数组以 `items` 包装，保持顺序 |
| `contentJson.widget` | 对象 | 原二维渲染配置镜像，用于按来源类恢复；不是第二份依赖归属 |

数据请求、`statusList`、`interactiveEvent`、设备绑定等从二维渲染正文提升至依赖包；不能只保存 `contentJson` 却遗漏三类依赖，也不能把图表运行实例和函数序列化进去。组件注册表图标属于当前前端资源，不固化到场景正文。

107 个有效组件的 `option` 差异由各自 `src/packages/components/*/*/config.ts` 定义，按配置原文保留即可；后端无需为每个图表建不同表。组件库升级的默认补齐由前端完成，服务端不要擅自删除旧选项。

### 3.2 视觉管理树

普通节点：`{id:string,type:"widget"}`。组节点：

```json
{"id":"group-1","type":"group","name":"设备信息组","visible":true,"locked":false,"children":["400001","400002"],"childGroupIds":[]}
```

- `children` 是直属部件编号；`childGroupIds` 是直属子视觉组编号，旧快照可缺省为空。
- 视觉分组只管理显隐、锁定、排序与整体变换，不创建真实组件父子关系；真实父子用 `parentInstanceId`。
- 树顺序与渲染次序相关，不得存入无序集合；校验循环、重复编号和非法引用。
- 分组显隐与部件自身显隐取交集；锁定取并集。隐藏组件仍需完整持久化。

### 3.3 图片、按钮与媒体

市场图片保存 `sourceType:"resource-market"` 与稳定 `resourceKey`，运行解析地址清空；外部资源按当前来源标记保存地址。按钮/测验每个图片槽位分别处理，普通/按下态共享图片只登记一次资源拥有者。

视频场景选项保存播放配置、来源及媒体服务器编号，不能保存播放器对象、协商会话、媒体管理密钥或 Unity 连接实例。按压反馈、分页当前记录、输入即时值等运行态不作为设计配置写入。

## 4. 三维内容包

```json
{
  "baseConfig":{"scene":{},"camera":{},"weather":{},"coordinateSystem":{"kind":"local","unit":"meter","upAxis":"Y","gridEnabled":true},"gisLayers":[]},
  "objects":[],"components":[],"layers":[],
  "streaming":{"groups":[],"chunks":[],"chunkTargets":[],"options":{}},
  "cameraPaths":[]
}
```

| 字段 | 数据结构 |
| --- | --- |
| `baseConfig` | 场景、相机、天气、坐标系、地理图层等基础配置对象，按来源模型原样保存 |
| `objects` | 普通三维目标数组 |
| `components` | 灯光、特效等来源三维组件数组，不能混入二维组件 |
| `layers` | 三维图层描述数组 |
| `streaming` | 组、区块、目标关系与编辑/预览策略 |
| `cameraPaths` | 相机路径数组，路径与点顺序不可丢失 |
| `vegetation` | 可选，整个场景的植被配置聚合，见专项文件 |

三维目标：`instanceId,targetType,name?,visible,locked,layerKey?,sortNo,transform,resourceRefKeys,contentJson`。正式 `instanceId` 对应领域对象 `id`；`contentJson` 包含模型、灯光、打点、特效及第一人称等私有配置，不保存引擎对象。父级和业务扩展以来源投影保留。

来源局部变换为 `{kind:"local",position:[x,y,z],rotation:[x,y,z],scale:number或[x,y,z]}`；地理变换为 `{kind:"geo",longitude,latitude,height,heading,pitch,roll,scale,…}`，字段和单位以附录当前类型为准。**它们与 Unity 四元数协议不同，后端持久化不能直接换成旧 `UnityTransformDto`。**

图层：`layerKey,layerType,name,visible,locked,sortNo,opacity?,provider?,url?,resourceRefKeys?,options?,metadata?`。资产型图层通过稳定资源引用解析地址；直连切片若没有稳定资产编号，`url` 或项目路径是实际配置，不能一概删掉所有网址。

流式区块：由来源 `SceneChunk/StreamingGroup/BoundingVolume/SceneStreamingConfig` 投影，区块含场景、空间边界、目标编号、距离与优先级等。完整结构在附录；相机移动只用本地索引调度，不要求后端每帧提供可见模型列表。植被海量实例不展开成 `objects` 中每株一个目标。

## 5. 依赖包

```json
{"resources":[],"dataBindings":[],"behaviors":[],"deviceBindings":[]}
```

### 5.1 拥有者

```json
{"domain":"twoD","ownerType":"instance","instanceId":"400001"}
```

`domain=twoD/threeD`。普通实例 `ownerType=instance` 携带 `instanceId`；图层/特效/其他聚合可用自己的 `ownerType` 与 `ownerKey`。不能把无实例的场景动作伪造成实例行为。服务端索引至少包含域、拥有者类型、实例编号或拥有者键，不只按 `instanceId` 一列粗略去重。

### 5.2 资源依赖

```json
{"resourceKey":"resource-model-1","assetId":"500001","kind":"glb","owners":[{"domain":"threeD","ownerType":"instance","instanceId":"600001"}],"contentHash":"资源摘要","loadOptions":{},"materialProfile":{}}
```

`resourceKey` 为场景内引用键；`assetId` 为市场/文件稳定身份，两者语义不同，示例允许相同但不能强制相等。`kind` 为资源格式。`owners` 可有多个二维和三维消费者；删除一侧引用只移除对应拥有者，不能删另一侧资源。

资源可带摘要、材质规则、加载参数与低细节资源策略；细节类型参见附录的 `AssetRef/ModelMaterialProfile/ModelLodVariant`。不要保存临时签名地址或令牌。植被物种、发布清单及瓦片归 `threeDJson.vegetation` 和专用发布资源接口，不重复混入普通 `resources` 作为第二事实来源。

### 5.3 实例数据绑定

```json
{
  "bindingKey":"request-1","owner":{"domain":"twoD","ownerType":"instance","instanceId":"400001"},
  "source":{"type":"static","requestConfig":{"data":[{"value":"在线"}]},"staticData":[{"value":"在线"}]},
  "extractorConfig":{"resultPath":""},"schemaConfig":{"dimensions":["value"]},
  "mappingConfig":{"bindings":[{"kind":"widget","targetPath":"value","sourceField":"value","valueType":"string"}],"deletedAutoMappingTargets":[]},
  "filterConfig":{},"refresh":{"mode":"manual"},"enabled":true,"sortNo":0,
  "contentJson":{"dataConfigVersion":2,"requestSnapshot":{"id":"request-1","name":"请求1","request":{"type":"static","config":{"data":[{"value":"在线"}]}},"dataset":{"dimensions":["value"],"source":[{"value":"在线"}]},"bindings":[{"kind":"widget","targetPath":"value","sourceField":"value","valueType":"string"}]}}
}
```

| 字段 | 含义/约束 |
| --- | --- |
| `bindingKey` | 拥有者内部请求编号，不要求跨实例全局唯一；唯一键是拥有者身份加此键 |
| `source.type` | 当前 `static/dataset/ajax/public`；历史数据集兼容不等于恢复旧持久化方案 |
| `source.requestConfig` | 当前数据源参数，见下一小节 |
| `source.publicRequestKey` | 仅公共接口引用，必须存在于 `sceneJson.publicRequests` |
| `source.staticData` | 只有静态源保存实际数据；其他类型为 `null` 或按来源投影保留 |
| `extractorConfig.resultPath` | 从响应取值的路径，如 `data.rows` |
| `schemaConfig.dimensions` | 字段结构，不是最近网络结果 |
| `mappingConfig.bindings` | 图表/部件/对象映射列表；每条结构见附录 |
| `mappingConfig.deletedAutoMappingTargets` | 用户删除的自动映射目标，避免恢复后重加 |
| `filterConfig.filterFn` | 用户过滤定义字符串，后端保存但不执行 |
| `refresh.mode` | 当前 `polling/manual` |
| `refresh.intervalMs` | 正数轮询毫秒，仅轮询模式需要；由原间隔/单位换算 |
| `enabled,sortNo` | 启用及请求顺序 |
| `contentJson.requestSnapshot` | 原请求项纯数据，用于编辑面板逆向恢复，不得丢失 |

异步请求配置（`AjaxRequestConfig`）完整字段：`requestHttpType` 为 `GET/POST/PUT/PATCH/DELETE`；`requestInterval:number或null`；`requestIntervalUnit=second/minute/hour/day`；`requestOriginUrl,requestUrl`；可选 `requestName,requestHeaders,requestQuery,requestBody,resultPath,useAuth`；`requestContentType=default/sql`；`requestParamsBodyType=none/json/xml/form-data/x-www-form-urlencoded`；`requestParams={Params,Header,Body:{form-data,x-www-form-urlencoded,json,xml}}`；`requestSQLContent={sql:string}`。

编辑器 `ComponentDataConfig` 的版本当前 2，`requests` 最多 5 项，每项 `id,name,collapsed?,request,extractor?,dataset,bindings,filterFn?,deletedAutoMappingTargets?`。根级 `request/extractor/dataset/bindings/filterFn` 是请求 1 镜像，后端不能另当一组数据源。预览动态结果只留内存；当前 `requestSnapshot` 原文较宽，联调应专测动态 `dataset.source` 是否仍夹带结果，未验证前不得宣称已自动彻底净化。

### 5.4 行为、条件和动作

```json
{
  "behaviorKey":"event-1","owner":{"domain":"twoD","ownerType":"instance","instanceId":"400001"},
  "behaviorType":"interaction","name":"点击显示","eventType":"click","enabled":true,"sortNo":0,
  "conditionGroups":[{"conditionGroupKey":"condition-group-1","conditionRuleType":"all","conditions":[],"actions":[{
    "actionKey":"action-1","actionType":"widgetVisibility","targets":[{"domain":"twoD","ownerType":"instance","instanceId":"400002"}],
    "config":{"id":"action-1","actionType":"widgetVisibility","actionTargetWidgetIds":["400002"],"widgetVisibility":true}
  }]}],
  "contentJson":{"legacyConfig":{"id":"event-1","eventName":"点击显示","eventType":"click","isOpen":true,"conditionGroupList":[]}}
}
```

例子为结构说明；生产保存的 `legacyConfig` 包含完整原配置，不能用例子中的空条件组覆盖真实事件。`behaviorType=status/interaction`；交互有点击、双击、移入、移出及专用子项事件。`conditionGroups` 按来源组/块拍平但保留顺序。

条件：`conditionKey,enabled,judgment,left:{kind,value,valueType?},right:{kind,value,valueType?},contentJson`；动作：`actionKey,actionType,targets:Owner[],observationTargets?:Owner[],config`。`contentJson/config` 保留跨部件引用、子项、参数来源、动作等待及专用设置。完整枚举和原字段见附录；不能把后端未知的动作类型删除。三维动作持久化可先支持原文，实际执行等 Unity 协议支持。

**子项事件差异：**页面菜单等部件的部分子项事件保存在组件私有配置，不全来自顶层 `interactiveEvent`。后端必须保留整个渲染私有对象，不能只索引顶层事件后丢掉子项配置。

### 5.5 设备绑定

基本结构：`{bindingKey:string,owner:Owner,deviceId?:string,…扩展}`，原 `deviceBinding` 中的通道及映射字段保留。当前没有独立设备注册/查询的完整契约；不得据此臆造物联网平台接口。后端可按拥有者建立查询索引，业务设备权限与通道订阅另行定义。

## 6. 模板域裁剪

| 范围 | 保留内容 |
| --- | --- |
| `twoD` | 二维组件/画布/树及其依赖；三维清空为默认槽位，可跨场景类型使用 |
| `threeD` | 三维内容及依赖；二维空白默认；必须保持原场景类型 |
| `all` | 两域完整复制；三维类型必须匹配 |

保留依赖拥有者闭包与仍使用的公共接口；有动态或公共请求时保留全局请求配置。动作保留并清理越界目标；条件保留，仅清理越界一侧引用，不能整条删除用户行为。操作模板副本，不反改源场景。画布覆盖应用按当前恢复链保持模板内部引用自洽；服务端 `fromTemplate` 新建实例则按来源设计重新编号并同时改写所有内部引用，两种操作不能混用。

普通保存混合场景不能套用模板裁剪逻辑；二维删除资源只删除二维拥有者，三维和未知域原样保全。第一阶段有明确用户确认的二维模板覆盖是例外：当前场景的三维内容按来源规则清空。

## 7. 发布存储与按需查询

后端发布时保存不可变四包快照，并从 `dependenciesJson` 解析每条 `owner/owners` 供实例依赖查询。可把完整原文与索引分开存储；索引不能改变原文、变更版本或跨发布复用错误资源。

三个完整包的返回字段仍是 JSON 字符串。实例依赖的四类数组元素各为单条依赖 JSON 字符串。普通资源共享时同一原文可能属于多个实例，按请求实例查询时正确归类，前端再按稳定键合并。

依赖标识作用域：`resourceKey` 结合发布/场景；`bindingKey` 结合拥有者；`behaviorKey` 结合拥有者；组编号/实例编号在各自场景结构中唯一。后端批量匹配不得只看相同的 `request-1`。

## 8. 必须处理的旧数据与容量差异

1. 当前存在 `sceneJson.metadata.dataBindingOverflow` 兼容字段。来源旧后端曾只保存前 150 条绑定，前端把尾部备份在元信息并在加载时合并。**150 是旧后端缺陷，不是新后端上限。**新后台应完整存储所有绑定，保留该扩展并按拥有者联合键防重复；是否移除兼容备份须与前端共同迁移。
2. `recoverKnownSceneDependenciesJson` 等历史修复仅服务旧数据，不能设计一个会输出损坏 JSON、依赖前端修复的新后端。
3. 场景公共接口/全局配置/场景动作以 `sceneJson` 为准；旧快照放在依赖包时可兼容读取，但新保存不继续复制旧镜像。
4. 新后端要声明正文总大小、单包大小、实例数和依赖批量上限；超限拒绝且不部分写入。禁止无提示截断列表、字符串或组件选项。
5. 未支持的模型资产、地理图层和三维字段保持原文，后续由能力协商决定是否执行；不能因 Unity 暂不支持而删字段。

## 9. 四包验收样例要求

后端交付时至少准备空场景、纯二维、二维分组/真实父子、多请求图表、公共请求复用、含子项事件的页面框架、市场图片共享、二维与三维混合、植被发布引用、未知扩展、超过 150 条数据绑定这些样例。

每项执行：读取 → 前端恢复 → 修改二维 → 一次保存 → 再读四包比较 → 发布 → 按票据读取 → 首次显示隐藏实例取依赖。对未编辑三维和未知扩展做精确比较；对业务索引和稳定编号做语义比较；模拟中断和并发验证原子性。
