# 独立登录鉴权设计与环境切换

日期：2026-10-20。适用范围：本项目独立运营端与租户端模式。状态：登录、资料、退出适配已实现；自建业务后端尚待开发；续期为新增设计，默认关闭。

后端可直接阅读 [主交接文档第 3.1 节](01-业务接口与后端实施契约.md#31-独立模式)获取完整协议。本文件补充参考接口证据、环境配置和前端集成细节；字段口径以主交接文档为准。

## 1. 决策与接口依据

独立模式不沿用历史管理鉴权与地址发现接口。独立认证和场景、资源、字典共用 `VITE_DIM3D_SERVER_URL` 的协议、主机、端口，不增加专用认证服务器地址。所有接口采用业务成功封套 `code=200`。

参考三维项目的现代独立认证属于预留能力，游客登录只服务公开预览。为避免将游客身份用于管理页面，本轮只读核对了配套运营端 `D:/WorkSpace/GitWorkSpace/amm-operation-web`：

| 依据 | 已确认的代码契约 |
| --- | --- |
| `src/apis/auth/tokenkongzhi.ts` | 登录 `/auth/operation/login`，退出 `/auth/logout` |
| `src/views/Login/components/LoginForm.vue`、`enum.ts` | 密码登录提交 `clientId,accountType=2,phonenumber,password,grantType=password` |
| `src/apis/auth/types.ts` 的 `LoginVo` | 令牌字段 `access_token,client_id,expire_in,refresh_token,refresh_expire_in` |
| `src/apis/system/yonghuxinxi.ts`、`types.ts` | 用户信息 `/system/user/getInfo`，`data={user,roles,permissions}` |
| `src/config/axios/request.ts`、`.env.dev` | 配套运营端服务根已经含 `/api/`；成功码 200，请求头 `Authorization` 和 `clientId` |
| 已部署租户端 `http://192.168.10.200:30083` 的公开构建模块 | 登录 `/auth/tenant/login`；当前资料 `/tenant/profile/getInfo`；应用编号为参考租户应用公开编号 |
| 来源三维项目 `.env.development` | 当前业务服务器、对象存储、数据中间件和宿主白名单 |

本项目认证适配器明确自行拼接一次 `/api`，因此环境变量只写服务器根。认证接口不进入 `operation/tenant/web` 自动插段流程。浏览器请求头名称不区分大小写，统一书写 `ClientId`。

参考代码未找到可确认的现代续期端点，不能把旧刷新接口迁来或宣称 `/api/auth/refresh` 已经存在。当前过期重新登录；自建后端实现本文件续期契约后再打开环境开关。

核验边界：已经无凭据读取参考服务器 `/api/system/user/getInfo`，得到传输状态 200、业务码 401，说明路径可达且服务要求认证。登录路径的无凭据跨域预检也已返回 200，并允许本地来源和提交方法。未使用真实账号执行登录、注销或后端写入，登录成功链路通过隔离模拟接口验证。来源令牌类型未直接标注时间单位，但来源 `src/utils/utils.ts` 的游客消费将 `expire_in` 乘 1000，本项目同样按剩余秒数实现；自建后端必须按下文秒单位实现。

## 2. 环境配置与切换

| 变量 | 含义 | 当前配置/规则 |
| --- | --- | --- |
| `VITE_DIM3D_SERVER_URL` | 认证和业务统一根地址 | 开发示例复用参考服务器 `http://192.168.10.200:30080`，不得含 `/api` |
| `VITE_AUTH_OPERATION_CLIENT_ID` | 独立运营登录应用编号 | 当前沿用参考运营应用的公开编号 |
| `VITE_AUTH_TENANT_CLIENT_ID` | 独立租户登录应用编号 | 当前沿用参考租户应用的公开编号；不读取游客变量 |
| `VITE_AUTH_CLIENT_ID` | 旧配置兼容项 | 只作为运营编号缺失时的回退，租户禁止回退到运营应用 |
| `VITE_AUTH_REFRESH_ENABLED` | 允许调用新增续期接口 | 当前 `false`；自建后端实现并验收后才启用 |
| `VITE_EMBED_MODE` | 宿主嵌入模式开关 | 独立 `false`；内嵌 `true` |
| `VITE_BASE_URL` | 网页部署子路径 | `/threeWeb/`，与接口路径无关 |
| `VITE_DIM3D_AMM_SERVER_URL` | 静态对象存储根 | 独立配置，不作为认证服务器 |
| `VITE_DATA_MIDDLEWARE_URL`、`VITE_DATA_MIDDLEWARE_PREFIX` | 数据中间件及本地代理前缀 | 沿用参考配置，不作为登录服务器 |
| `VITE_OPERATION_ORIGIN(S)` | 预览登录宿主及嵌入白名单 | 沿用实际宿主来源；不是独立登录地址 |

`VITE_SERVER_URL`、`VITE_LOGIN_URL` 已从当前独立模式配置和开发代理移除。部署不再需要旧管理后台或旧统一登录页。公开预览游客配置继续沿用原逻辑；独立租户登录使用用户输入的账号密码，不读取游客账号配置。

操作步骤：

1. 当前 `.env.development.local` 与 `.env.example` 使用参考项目的非敏感业务地址；密码、令牌不写环境示例。
2. 本项目后端按相同 `/api` 路径、响应字段及运营/租户两套业务路由实现，注册允许本项目使用的登录应用。
3. 后端开发完成后，将 `.env.development.local` 或 `.env.production.local` 中 `VITE_DIM3D_SERVER_URL` 改为新服务器根。如果应用编号不同，同步修改对应的 `VITE_AUTH_OPERATION_CLIENT_ID` 或 `VITE_AUTH_TENANT_CLIENT_ID`。对象存储或中间件迁走时分别改对应变量。
4. 实现并验收续期后，再将 `VITE_AUTH_REFRESH_ENABLED=true`；不启用也能通过过期重新登录使用系统。
5. 开发服务器需重启；生产前端需重新构建部署。构建环境变量不是运行时远程配置，不能只改服务器上的文本而不重新构建。
6. 新服务器地址与会话绑定，切换后需重新登录，禁止把参考服务器令牌发送给新后端。

跨域部署时，后端按实际网页来源开放跨域资源共享（CORS），支持 `Authorization,ClientId,Content-Type` 和相关请求方法及预检请求。认证不依赖跨域浏览器凭据；同源生产网关可以转发 `/api`。网页服务器为 `/threeWeb/` 提供前端路由回退。

## 3. 接口总表

所有路径均位于同一个业务服务器。

| 方法 | 完整公共路径 | 是否需要用户令牌 | 当前参考能力 | 自建后端要求 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/operation/login` | 否 | 配套运营端已有调用 | 运营登录必做 |
| POST | `/api/auth/tenant/login` | 否 | 已部署租户端现有调用 | 租户登录必做 |
| GET | `/api/system/user/getInfo` | 是 | 已有调用且未登录读取可达 | 运营资料必做 |
| GET | `/api/tenant/profile/getInfo` | 是 | 已部署租户端现有调用 | 租户资料必做 |
| POST | `/api/auth/logout` | 是 | 配套运营端已有声明，尚未真实注销验证 | 首批必做 |
| POST | `/api/auth/refresh` | 不使用访问令牌，凭刷新令牌 | 尚未确认存在，当前禁止调用 | 新增设计，按续期需求开发 |

独立登录页提供“运营端 / 租户端”切换，提交期间锁定选项，切换时清空密码及错误提示。两端分别认证，不复用另一端会话。运营业务走 `/api/operation/...`，租户业务走 `/api/tenant/web/...`。认证端点保持上表原始路径，不自动插段；不新增注册、找回密码、短信、验证码或菜单管理接口。内嵌鉴权和公开预览游客接口保持原协议。

## 4. 手机号密码登录

`POST /api/auth/operation/login` 用于运营端，`POST /api/auth/tenant/login` 用于租户端；两者内容类型 `application/json`。不得把密码放入查询参数、网址或日志。

```json
{"clientId":"所选平台应用编号","accountType":2,"phonenumber":"13800000000","password":"用户输入的密码","grantType":"password"}
```

| 字段 | 类型 | 必填 | 校验与含义 |
| --- | --- | --- | --- |
| `clientId` | 字符串 | 是 | 后端已登记并允许对应端密码登录的应用；前端公开标识，不能当作秘密 |
| `accountType` | 整数 | 是 | 当前固定 2，表示手机号；不接收游客或用户类型的隐式切换 |
| `phonenumber` | 字符串 | 是 | 当前界面验证中国大陆手机号；去首尾空格，不能转成整数 |
| `password` | 字符串 | 是 | 按原值验证，不裁剪或返回；长度上限由后端账户策略冻结 |
| `grantType` | 字符串 | 是 | 当前固定 `password`；未经实现的授权类型必须拒绝 |

自建后端成功响应：

```json
{"code":200,"msg":"登录成功","data":{"access_token":"不透明访问令牌","client_id":"所选平台应用编号","expire_in":1800,"refresh_token":"不透明刷新令牌","refresh_expire_in":604800}}
```

| 响应字段 | 类型 | 自建后端约束 |
| --- | --- | --- |
| `access_token` | 非空字符串 | 必填，不含 `Bearer` 前缀，不能含密码或可逆账户秘密 |
| `client_id` | 非空字符串 | 必填，应与已验证的应用对应；后续请求按响应值发 `ClientId` |
| `expire_in` | 正整数 | 必填，访问令牌剩余秒数，例如 1800；不是毫秒或时间戳 |
| `refresh_token` | 非空字符串 | 启用续期时必填；只供刷新，不得用来访问场景/文件 |
| `refresh_expire_in` | 正整数 | 启用续期时必填，刷新令牌剩余秒数 |

参考服务兼容两个有效期和刷新令牌缺失或显式为 `null`。可选字段的 `null` 表示未提供，不属于格式错误，也不能转换为零秒。访问有效期为合法正数时按秒计算；缺失或为 `null` 时不猜测期限，以后端 401 为准。未返回有效刷新令牌时不发起续期，不能因此拒绝已经成功的访问登录。自建后端仍按上表返回访问有效期；只有启用续期时才必须返回完整刷新字段。`scope/openid` 如来源返回可忽略，不影响场景业务。成功后必须再获取用户资料；两步均成功才挂载业务页面。资料请求失败不能伪造角色和权限。

参考服务未签发刷新令牌的合法示例（示例令牌为占位值）：

```json
{"code":200,"msg":"操作成功","data":{"access_token":"访问令牌占位值","expire_in":604800,"refresh_token":null,"refresh_expire_in":null,"client_id":"所选平台应用编号"}}
```


失败使用下文错误语义；账号不存在、密码错误统一提示“手机号或密码错误”，避免枚举账户。限制连续失败、应用访问权限和停用账户；口令采用带盐不可逆算法保存，禁止明文存储。推荐生产使用安全超文本传输协议（HTTPS）。

## 5. 当前用户与权限

`GET /api/system/user/getInfo` 用于运营端；`GET /api/tenant/profile/getInfo` 用于租户端。无请求体，两端共有 `user/roles/permissions`，但显示名称字段不同。租户资料路径不含 `/web`，也不经过平台自动插段。

```http
Authorization: Bearer <访问令牌>
ClientId: <登录响应的client_id>
```

```json
{"code":200,"msg":"查询成功","data":{"user":{"userId":"100001","tenantId":"100","deptId":"1001","userName":"scene-editor","nickName":"场景编辑员","avatar":"","phonenumber":"13800000000"},"roles":["scene_editor"],"permissions":["scene:read","scene:edit"]}}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `user` | 对象 | 必填，不含密码散列、刷新令牌等秘密 |
| `user.userId` | 字符串 | 必填，稳定用户编号；参考端数字仅为前端兼容 |
| `user.nickName` | 字符串 | 运营端必填；租户端可缺失或为 `null`，有非空昵称时优先用于显示 |
| `user.tenantId` | 字符串 | 可选归属信息；实际数据权限由服务端按身份确定 |
| `user.deptId` | 字符串 | 可选部门编号 |
| `user.userName` | 字符串 | 参考租户端实际返回的用户名称；租户未提供昵称时必填并作为显示名。运营端为可选账号标识，不代替手机号登录输入 |
| `user.avatar` | 字符串或空值 | 可选头像地址，空字符串或 `null` 合法；前端投影时省略空值 |
| `user.phonenumber` | 字符串 | 可选手机号，按展示策略脱敏 |
| `roles` | 字符串数组 | 必填，合法空数组表示无角色；不能返回角色对象数组 |
| `permissions` | 字符串数组 | 必填，合法空数组表示无已授权限；服务端按业务权限校验每次请求 |

独立前端按成功登录入口保存 `platformType=operation/tenant`，用于选择页面能力和业务路径，不是权限授予。后端必须校验登录应用、账户平台资格和租户归属，并拒绝租户身份访问运营资源；不得因为路径含 `operation` 就视作管理员。不要为迁移便利向全部登录用户返回 `admin` 或 `*:*:*`。

参考租户端的实际资料与运营端不是完全相同的用户字段，合法示例：

```json
{"code":200,"msg":"操作成功","data":{"user":{"userId":"100001","tenantId":"100","deptId":"1001","userName":"租户用户","avatar":null},"permissions":["scene:read"],"roles":[]}}
```

参考租户资料已通过只读请求核对：`userId` 为字符串，名称为 `userName`，未返回 `nickName`，`roles` 为空数组仍是合法已登录身份。前端只在资料适配边界将租户名称投影为内部 `nickName`，不要求修改参考后端。用户编号及权限数组仍严格校验，不能用名称补造身份或授予角色。首次登录和页面刷新恢复使用同一适配，保持租户平台不变。

刷新页面重新查询资料，及时获取权限变化。现有管理入口部分能力按平台类型映射，前端不作为最终权限边界；后端必须检查场景编辑、发布、资源修改、模板和跨租户权限。

## 6. 续期：新增自建协议

`POST /api/auth/refresh`，仅 `VITE_AUTH_REFRESH_ENABLED=true` 时允许前端调用。内容类型 `application/json`，不附加失效的访问令牌。

```json
{"clientId":"所选平台应用编号","refreshToken":"上次返回的刷新令牌","platformType":"tenant"}
```

三个字段均必填：`clientId`、`refreshToken` 为非空字符串，`platformType` 为 `operation/tenant`。刷新平台和应用必须与原会话一致，不允许续期变更平台或租户。成功封套与登录相同，五个令牌字段均必填，秒单位不变。后端原子校验应用、会话、用户状态和刷新令牌有效期，轮换访问/刷新令牌；提交成功后旧刷新令牌不可再次换取身份。刷新令牌仅保存摘要，记录会话编号、用户、应用、期限、撤销状态和轮换链；检测旧令牌重放后撤销相应会话。

前端并发 401 共享同一次续期，失败也会结束全部等待，不保留悬挂队列。成功后每个原业务请求最多重放一次；重复 401 返回登录状态，不无限循环。只有确实使用独立身份的第一方请求可续期，公开预览票据、宿主身份、外部数据源、自配请求头不得触发本接口。

当前仅确认 401 表示未认证时参与续期；权限不足必须使用 403，不能用 401 混淆角色不足与登录过期。前端保留已知资源权限提示的兼容隔离。

**幂等与重放限制：**业务请求被 401 拒绝时必须在业务事务开始前完成鉴权，不得先写入后再返回 401；否则自动重放会重复操作。保存等写接口继续使用已有请求编号幂等机制。

## 7. 主动退出

`POST /api/auth/logout`，携带访问令牌与 `ClientId`，正文 `{}`，成功：

```json
{"code":200,"msg":"退出成功","data":null}
```

后端撤销当前用户、应用对应的当前会话和刷新令牌链，不默认退出其他设备。重复注销应幂等。若访问令牌已过期可返回 401；前端仍清理本地身份。

前端点击退出立即清空内存及当前页签独立会话，再请求远端注销。远端失败不恢复本地身份。退出清理兼容旧会话键及当前页签交接缓存；不会删除用户无关浏览器数据。正在续期或恢复的迟到响应不得恢复已退出的身份。

已有编辑器/预览子页签可能持有短时交接副本；本轮不新增跨页签退出广播，后端必须通过会话撤销让旧副本的后续受保护请求返回 401。未发请求的子页签不会立即收到注销通知；如需即时退出显示，另加同源广播协议。

## 8. 状态、存储与集成边界

平台展示规则见 [主文档第 3.1.0 节](01-业务接口与后端实施契约.md#310-登录平台选择与展示规则)，复用现有 `capabilities.ts`，不复制两套业务页面。

独立模式启动：消费受信页签交接 → 恢复本地独立会话 → 后端重验资料 → 业务页面；没有有效身份显示本项目登录表单。未完成认证不挂载业务路由，不请求旧服务发现。

仅当前页签的会话存储（sessionStorage）保存本次独立会话，键为 `wx-unity:standalone-session:v2`；包含服务器标识、`platformType`、令牌、绝对到期时间和资料投影，不含密码。存储受限时仅保留内存，刷新后需登录。服务器变更或平台值无效时拒绝旧会话。缺失平台的第一版独立会话不恢复，需重新登录。此存储不替代服务端认证或授权。

内嵌模式继续由父页面传入令牌、应用编号、平台、角色和权限；不调用本文件独立登录、续期和退出接口。独立编辑/预览页签沿用受信交接，不把独立刷新令牌复制给子页签。公开预览仍按原解析/游客/票据流程；此文件不把游客登录升级为运营身份。

旧网址参数 `accessToken/refreshToken/expiresTime` 只清除、不再接收为认证依据。独立请求失效时管理页显示登录；编辑器保留当前内存画布并提示关闭后重新进入，避免静默卸载导致未保存内容丢失。

认证适配器：[独立认证模块](../../src/auth/standalone.ts)；组合入口：[应用入口](../../src/App.vue)；表单：[独立登录页](../../src/views/StandaloneLogin.vue)；业务注入与续期：[请求层](../../src/request.ts)。

## 9. 错误、后端实现与验收

错误封套固定 `{code:number,msg:string,data:null}`，不得把异常堆栈、账号秘密或令牌回显到消息。前端兼容传输状态 200 携带业务 401；新后端推荐传输状态与业务码一致。

| 状态/业务码 | 含义 | 前端动作 |
| --- | --- | --- |
| 400/422 | 参数或授权类型不合法 | 展示可读错误，不建立会话 |
| 401 | 口令错误、访问或刷新身份无效 | 登录页提示；受保护业务按续期开关处理 |
| 403 | 应用/账号被禁止、角色不足 | 明确拒绝，不自动续期 |
| 429 | 请求频率超限 | 展示限流；支持服务端重试等待提示 |
| 500/503 | 服务不可用 | 明确失败，不伪登录或返回空权限成功 |

后端首批实现顺序：用户与口令存储 → 应用登记与授权 → 登录会话签发 → 当前资料与权限 → 受保护业务令牌校验 → 注销撤销；按需求实现原子续期后再启用开关。角色/权限可复用现有业务模型，不要求新增菜单接口。审计只记用户/应用、动作、结果、会话追踪编号及时间，不记原始令牌、密码。

验收覆盖：正确/错误口令、停用用户、未授权应用、失效令牌、大编号、空权限、跨租户拒绝、同一根地址、平台不重复插段、刷新页面、切换服务器后重新登录、注销失败本地仍退出、并发续期单次请求、续期失败全部结束、旧刷新令牌重放、重试最多一次、第三方 401 不刷新、公开票据 401 不影响运营会话、内嵌鉴权不走独立流程。

本文件冻结的是本项目开发契约；参考端登录成功和令牌过期行为仍须有授权测试账号联调确认。未验证能力已明确标识，不要求参考后端提前实现新增端点。
