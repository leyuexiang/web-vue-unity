# 业务接口与后端实施契约

版本：2026-10-20；状态：后端开发交接稿，待联调冻结。

## 1. 实现范围与证据优先级

本项目尚无配套业务后端，需要实现本文件中的管理、资源、场景、保存发布、鉴权和媒体接口，并预留 [三维专项与云渲染接口](03-Unity云渲染与三维专项接口.md)。页面功能与业务流程沿用参考项目，浏览器三维呈现后续换为 Unity 云渲染。

契约核对顺序：当前请求适配器和真实消费代码 → 来源真实契约维护文档的较新条目 → 来源 43、44 号设计。发生矛盾时在第 12 节登记，不能混合成一套看似已确定的新协议。特别是前端的兼容可选字段、异常兜底、错误路径，不等同于后端设计要求。

| 阶段 | 接口范围 | 前端现状 |
| --- | --- | --- |
| 第一批 | 登录、权限、字典、租户、场景列表、详情、编辑锁、四包保存 | 页面已经依赖，需要优先开发 |
| 第二批 | 图片/模型/模板管理、上传、文件解析、模板另存、发布与预览 | 已迁入调用链；三维显示尚未接入 |
| 二维媒体 | 媒体服务器列表与源流解析、播放器协议 | 项目含可复用的本地服务实现，生产仍需部署与业务鉴权 |
| 后续三维 | 地理信息、植被生成/发布/动态窗口、公开资源、云渲染会话、信令和运行时 | 含已保留调用与来源待迁移实现，详见专项文件 |

不得为每个二维部件、图表、三维模型实例单独新增增删改查接口。它们是场景四包里的实例；场景中的单次移动、属性修改和撤销均在前端内存完成，点击保存才整体提交。

## 2. 服务地址、路径与鉴权

### 2.1 路径记法

下文使用三类前缀。它们是逻辑记号，不是可直接发送的字面量。

| 记号 | 实际地址 | 用途 |
| --- | --- | --- |
| `业务前缀` | 运营端 `/api/operation`；租户端 `/api/tenant/web` | 场景、资源管理、模板、植被、预览 |
| `公共前缀` | `/api` | 对象存储、模型文件元信息、上传转换、字典、游客登录 |
| `独立鉴权前缀` | `/api/auth`、`/api/system/user` | 与业务共用服务器的现代独立认证，不额外插平台段 |

业务、公共接口和独立登录鉴权统一来自 `VITE_DIM3D_SERVER_URL`；旧管理后台地址变量及其开发代理已停用。文件桶根地址来自 `VITE_DIM3D_AMM_SERVER_URL`，模型访问路径为该地址加 `/amm/` 及返回的 `resourceRelativePath`。不把局域网地址、令牌或临时签名写入契约样例。

前端访问基础路径 `/threeWeb/` 属于网页部署，不是业务接口前缀。内嵌宿主或受限预览需要登录回跳时必须保留这个末尾斜杠，不能返回 `/threeWeb?…`。独立登录使用本项目表单，不走旧登录回跳；网关不能把业务地址再加 `/threeWeb/`。

### 2.2 请求头与身份

普通受保护的业务、公共文件及字典请求：

```http
Authorization: Bearer <用户访问令牌>
ClientId: <应用客户端编号>
Content-Type: application/json
```

文件上传使用多部分表单（multipart/form-data），由浏览器设置边界，不手动发送固定的上述内容类型。

- `ClientId` 标识应用，不是用户、租户、编辑锁页签或云渲染会话编号。
- 租户和用户身份由后端验证令牌后确定，不信任请求体传入的租户归属。运营端可按权限查询/授权其他租户，租户端不能靠改路径获得运营权限。
- 独立模式在登录页选择运营端或租户端，成功后持久化该平台；内嵌模式和鉴权交接页签由宿主上下文提供 `platformType`、令牌、权限和角色。跨域凭据与白名单延续现有鉴权模块。
- 前端临时兼容 `jtyf.dim3d.temp-token`、`jtyf.dim3d.client-id` 本地配置，后端不以“是否来自本地存储”区分安全级别。
- 发布预览使用第 8 节的票据（ticket）。当前实现还可能注入已恢复的宿主/游客上下文；不要按来源旧文档的“全部匿名”一句话实现。

### 2.3 通用类型和响应

编号统一是字符串，包括 `id`、`sceneId`、`revisionId`、`publishedPublicationId`、`publicationId`、`ossId`、`modelFileId`、`tenantId`、`assetId`。即使数据库采用 64 位整数，网络上也必须以字符串发送。`revisionNo`、`lockVersion`、分页数和计数是整数，不是编号。

当前正式保存服务还要求场景编号符合正十进制整数字符串 `^[1-9]\d*$`；新后端若改用带字母的场景编号会被现有前端拒绝，需要联动修改。植被任务、资源稳定键等另有字符串语义，不能一概限制为数字。

| 类型 | 规范 |
| --- | --- |
| 字符串 | 文本及稳定编号；可选字段缺失与空字符串不能随意互换 |
| 布尔 | 真正的 `true/false`，不要用字符串 `"false"` |
| 数字 | 有限数；整数计数不超过浏览器安全整数范围 |
| 时间 | 来源部分字段只声明字符串；新后端建议统一带时区日期时间，例如 `2026-10-20T12:00:00+08:00`，具体格式联调冻结 |
| 空数组 | 合法“无记录”；鉴权/格式失败不能用空数组伪装 |

普通业务成功：

```json
{"code":200,"msg":"操作成功","data":null}
```

分页成功固定使用根级分页，不要求新后端实现前端的历史多层兼容：

```json
{"code":200,"msg":"查询成功","total":0,"rows":[]}
```

独立登录鉴权和业务服务成功码统一为 `200`；旧管理登录成功码 `0` 不再作为开发依据；媒体成功直接返回对象。

HTTP 表示超文本传输协议（HTTP）状态。可使用传输状态 `401/403/404/409/422/429/500/503` 配合业务消息，但既有业务可能使用传输状态 200 携带非成功 `code`；前端同时检查。来源没有完整业务错误数字注册表，下表是语义要求，不能自行宣称某个新数字已获兼容。

| 场景 | 必须表达的结果 |
| --- | --- |
| 未登录、过期 | 401 语义，不能返回成功空列表 |
| 无权限、越租户 | 403 语义，不泄露资源正文 |
| 不存在、已撤销发布 | 明确失败或预览机器码 |
| 数据校验失败 | 可读 `msg`，保留当前内存编辑状态 |
| 编辑锁失效 | 不写入，返回锁状态/业务错误；不能发放伪保存书签 |
| 修订冲突 | 保存 `data.conflict=true` 与当前 `conflictRevisionNo`，或明确冲突错误 |
| 超限/服务不可用 | 明确限流或服务错误，不能伪成功 |

## 3. 登录、权限与独立认证

### 3.1 独立模式

独立模式已退出历史管理鉴权和地址发现调用，不能据旧代码要求新后端提供 `/admin-api/system/auth/*` 或 `/admin-api/dimensions/signaling/get-address`。环境地址直接配置，不通过信令接口发现。

| 方法与公共路径 | 请求 | 响应与用途 |
| --- | --- | --- |
| `POST /api/auth/operation/login`（运营）或 `POST /api/auth/tenant/login`（租户） | `clientId,accountType:2,phonenumber,password,grantType:password` | `data={access_token,client_id,expire_in,refresh_token?,refresh_expire_in?}` |
| `GET /api/system/user/getInfo`（运营）或 `GET /api/tenant/profile/getInfo`（租户） | 访问令牌与 `ClientId` | `data={user:{userId,nickName,…},roles:string[],permissions:string[]}` |
| `POST /api/auth/logout` | 访问令牌、`ClientId`，正文 `{}` | `data:null`，撤销当前会话 |
| `POST /api/auth/refresh` | `clientId,refreshToken,platformType` | 轮换令牌结构；新增自建协议，参考模式默认不调用 |

两端登录、资料和共用退出采用参考平台的现代接口风格；续期是新增设计，未宣称参考服务已实现。独立登录已提供本项目表单，不再跳转旧登录页或接收网址中的原始令牌。内嵌与公开预览保持各自认证流程。

完整请求、响应、字段校验、错误与会话规则如下，后端无需根据历史接口另行推断。

#### 3.1.0 登录平台选择与展示规则

| 登录选择 | 登录接口 | 当前用户接口 | 业务接口前缀 | 展示内容 |
| --- | --- | --- | --- | --- |
| 运营端 | `/api/auth/operation/login` | `/api/system/user/getInfo` | `/api/operation` | 沿用运营菜单和操作，开放模板管理、场景授权、场景文件导入/下载及另存模板 |
| 租户端 | `/api/auth/tenant/login` | `/api/tenant/profile/getInfo` | `/api/tenant/web` | 沿用租户菜单和操作，隐藏运营专属功能；系统资源只读，我的资源保留编辑/删除；发布支持个人、企业、公开加密和公开共享 |

登录选择只决定本次认证目标，必须通过该端真实认证后才能展示业务页面。会话保存平台，刷新页面和新开编辑/预览页签均保持该平台；租户直接进入模板路由会转到模型管理。重新选择另一端须在登录页重新认证，禁止只切换菜单并继续使用原令牌。旧身份的迟到请求或续期结果不得影响新平台会话。

#### 3.1.1 登录请求与令牌响应

`POST /api/auth/operation/login` 用于运营端，`POST /api/auth/tenant/login` 用于租户端；两者内容类型 `application/json`。不得把密码放入查询参数、网址或日志。

```json
{"clientId":"所选平台应用编号","accountType":2,"phonenumber":"13800000000","password":"用户输入的密码","grantType":"password"}
```

| 字段 | 类型 | 必填 | 校验与含义 |
| --- | --- | --- | --- |
| `clientId` | 字符串 | 是 | 后端已登记并允许对应端密码登录的应用；前端公开标识，不能当作秘密 |
| `accountType` | 整数 | 是 | 当前固定 2，表示手机号；不接收游客或用户类型的隐式切换 |
| `phonenumber` | 字符串 | 是 | 当前界面验证中国大陆手机号；去首尾空格，不能转成整数 |
| `password` | 字符串 | 是 | 按原值验证，不裁剪或返回；长度上限由后端账户策略冻结 |
| `grantType` | 字符串 | 是 | 当前固定 `password`；未经实现的授权类型必须拒绝 |

自建后端成功响应：

```json
{"code":200,"msg":"登录成功","data":{"access_token":"不透明访问令牌","client_id":"所选平台应用编号","expire_in":1800,"refresh_token":"不透明刷新令牌","refresh_expire_in":604800}}
```

| 响应字段 | 类型 | 自建后端约束 |
| --- | --- | --- |
| `access_token` | 非空字符串 | 必填，不含 `Bearer` 前缀，不能含密码或可逆账户秘密 |
| `client_id` | 非空字符串 | 必填，应与已验证的应用对应；后续请求按响应值发 `ClientId` |
| `expire_in` | 正整数 | 必填，访问令牌剩余秒数，例如 1800；不是毫秒或时间戳 |
| `refresh_token` | 非空字符串 | 启用续期时必填；只供刷新，不得用来访问场景/文件 |
| `refresh_expire_in` | 正整数 | 启用续期时必填，刷新令牌剩余秒数 |

参考服务兼容两个有效期和刷新令牌缺失或显式为 `null`。可选字段的 `null` 表示未提供，不属于格式错误，也不能转换为零秒。访问有效期为合法正数时按秒计算；缺失或为 `null` 时不猜测期限，以后端 401 为准。未返回有效刷新令牌时不发起续期，不能因此拒绝已经成功的访问登录。自建后端仍按上表返回访问有效期；只有启用续期时才必须返回完整刷新字段。`scope/openid` 如来源返回可忽略，不影响场景业务。成功后必须再获取用户资料；两步均成功才挂载业务页面。资料请求失败不能伪造角色和权限。

参考服务未签发刷新令牌的合法示例（示例令牌为占位值）：

```json
{"code":200,"msg":"操作成功","data":{"access_token":"访问令牌占位值","expire_in":604800,"refresh_token":null,"refresh_expire_in":null,"client_id":"所选平台应用编号"}}
```


失败使用下文错误语义；账号不存在、密码错误统一提示“手机号或密码错误”，避免枚举账户。限制连续失败、应用访问权限和停用账户；口令采用带盐不可逆算法保存，禁止明文存储。推荐生产使用安全超文本传输协议（HTTPS）。

#### 3.1.2 当前用户、角色与权限

`GET /api/system/user/getInfo` 用于运营端；`GET /api/tenant/profile/getInfo` 用于租户端。无请求体，两端共有 `user/roles/permissions`，但显示名称字段不同。租户资料路径不含 `/web`，也不经过平台自动插段。

```http
Authorization: Bearer <访问令牌>
ClientId: <登录响应的client_id>
```

```json
{"code":200,"msg":"查询成功","data":{"user":{"userId":"100001","tenantId":"100","deptId":"1001","userName":"scene-editor","nickName":"场景编辑员","avatar":"","phonenumber":"13800000000"},"roles":["scene_editor"],"permissions":["scene:read","scene:edit"]}}
```

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `user` | 对象 | 必填，不含密码散列、刷新令牌等秘密 |
| `user.userId` | 字符串 | 必填，稳定用户编号；参考端数字仅为前端兼容 |
| `user.nickName` | 字符串 | 运营端必填；租户端可缺失或为 `null`，有非空昵称时优先用于显示 |
| `user.tenantId` | 字符串 | 可选归属信息；实际数据权限由服务端按身份确定 |
| `user.deptId` | 字符串 | 可选部门编号 |
| `user.userName` | 字符串 | 参考租户端实际返回的用户名称；租户未提供昵称时必填并作为显示名。运营端为可选账号标识，不代替手机号登录输入 |
| `user.avatar` | 字符串或空值 | 可选头像地址，空字符串或 `null` 合法；前端投影时省略空值 |
| `user.phonenumber` | 字符串 | 可选手机号，按展示策略脱敏 |
| `roles` | 字符串数组 | 必填，合法空数组表示无角色；不能返回角色对象数组 |
| `permissions` | 字符串数组 | 必填，合法空数组表示无已授权限；服务端按业务权限校验每次请求 |

独立前端按成功登录入口保存 `platformType=operation/tenant`，用于选择页面能力和业务路径，不是权限授予。后端必须校验登录应用、账户平台资格和租户归属，并拒绝租户身份访问运营资源；不得因为路径含 `operation` 就视作管理员。不要为迁移便利向全部登录用户返回 `admin` 或 `*:*:*`。

参考租户端的实际资料与运营端不是完全相同的用户字段，合法示例：

```json
{"code":200,"msg":"操作成功","data":{"user":{"userId":"100001","tenantId":"100","deptId":"1001","userName":"租户用户","avatar":null},"permissions":["scene:read"],"roles":[]}}
```

参考租户资料已通过只读请求核对：`userId` 为字符串，名称为 `userName`，未返回 `nickName`，`roles` 为空数组仍是合法已登录身份。前端只在资料适配边界将租户名称投影为内部 `nickName`，不要求修改参考后端。用户编号及权限数组仍严格校验，不能用名称补造身份或授予角色。首次登录和页面刷新恢复使用同一适配，保持租户平台不变。

刷新页面重新查询资料，及时获取权限变化。现有管理入口部分能力按平台类型映射，前端不作为最终权限边界；后端必须检查场景编辑、发布、资源修改、模板和跨租户权限。

#### 3.1.3 令牌续期（新增待开发接口）

`POST /api/auth/refresh`，仅 `VITE_AUTH_REFRESH_ENABLED=true` 时允许前端调用。内容类型 `application/json`，不附加失效的访问令牌。

```json
{"clientId":"所选平台应用编号","refreshToken":"上次返回的刷新令牌","platformType":"tenant"}
```

三个字段均必填：`clientId`、`refreshToken` 为非空字符串，`platformType` 为 `operation/tenant`。刷新平台和应用必须与原会话一致，不允许续期变更平台或租户。成功封套与登录相同，五个令牌字段均必填，秒单位不变。后端原子校验应用、会话、用户状态和刷新令牌有效期，轮换访问/刷新令牌；提交成功后旧刷新令牌不可再次换取身份。刷新令牌仅保存摘要，记录会话编号、用户、应用、期限、撤销状态和轮换链；检测旧令牌重放后撤销相应会话。

前端并发 401 共享同一次续期，失败也会结束全部等待，不保留悬挂队列。成功后每个原业务请求最多重放一次；重复 401 返回登录状态，不无限循环。只有确实使用独立身份的第一方请求可续期，公开预览票据、宿主身份、外部数据源、自配请求头不得触发本接口。

当前仅确认 401 表示未认证时参与续期；权限不足必须使用 403，不能用 401 混淆角色不足与登录过期。前端保留已知资源权限提示的兼容隔离。

**幂等与重放限制：**业务请求被 401 拒绝时必须在业务事务开始前完成鉴权，不得先写入后再返回 401；否则自动重放会重复操作。保存等写接口继续使用已有请求编号幂等机制。

#### 3.1.4 退出登录与会话撤销

`POST /api/auth/logout`，携带访问令牌与 `ClientId`，正文 `{}`，成功：

```json
{"code":200,"msg":"退出成功","data":null}
```

后端撤销当前用户、应用对应的当前会话和刷新令牌链，不默认退出其他设备。重复注销应幂等。若访问令牌已过期可返回 401；前端仍清理本地身份。

前端点击退出立即清空内存及当前页签独立会话，再请求远端注销。远端失败不恢复本地身份。退出清理兼容旧会话键及当前页签交接缓存；不会删除用户无关浏览器数据。正在续期或恢复的迟到响应不得恢复已退出的身份。

已有编辑器/预览子页签可能持有短时交接副本；本轮不新增跨页签退出广播，后端必须通过会话撤销让旧副本的后续受保护请求返回 401。未发请求的子页签不会立即收到注销通知；如需即时退出显示，另加同源广播协议。

#### 3.1.5 错误响应与鉴权失败处理

错误封套固定 `{code:number,msg:string,data:null}`，不得把异常堆栈、账号秘密或令牌回显到消息。前端兼容传输状态 200 携带业务 401；新后端推荐传输状态与业务码一致。

| 状态/业务码 | 含义 | 前端动作 |
| --- | --- | --- |
| 400/422 | 参数或授权类型不合法 | 展示可读错误，不建立会话 |
| 401 | 口令错误、访问或刷新身份无效 | 登录页提示；受保护业务按续期开关处理 |
| 403 | 应用/账号被禁止、角色不足 | 明确拒绝，不自动续期 |
| 429 | 请求频率超限 | 展示限流；支持服务端重试等待提示 |
| 500/503 | 服务不可用 | 明确失败，不伪登录或返回空权限成功 |

```json
{"code":401,"msg":"登录状态已失效，请重新登录","data":null}
```

未认证或访问令牌过期使用 401；已登录但角色、租户或资源权限不足使用 403。业务接口必须在执行写事务前完成鉴权，防止 401 自动重放造成重复写入。

#### 3.1.6 服务配置与后端开发范围

- 登录、资料、退出、续期全部复用 `VITE_DIM3D_SERVER_URL`；不再配置独立鉴权主机或端口。
- 当前按所选平台调用参考服务器已有的登录、资料和共用退出接口；续期默认 `VITE_AUTH_REFRESH_ENABLED=false`，不得要求参考后端先提供新端点。
- 新后端按本节路径及字段实现，成功码统一 `200`，用户及部门编号返回字符串，令牌有效期返回剩余秒数。
- 新后端完成后修改统一业务根地址；应用编号变化时同步修改对应的 `VITE_AUTH_OPERATION_CLIENT_ID` 或 `VITE_AUTH_TENANT_CLIENT_ID`。开发重启、生产重新构建，切换服务器后重新登录。
- 内嵌认证、受信页签交接与公开游客登录分别沿用第 3.2、3.3 节，不把公开游客账号用于独立用户登录。

本节是独立模式后端实施正文；接口类型见 [字段附录第 21 节](04-现有类型与调用入口附录.md#21-独立登录与用户权限传输模型)。参考代码定位、环境示例及切换流程见 [独立鉴权环境与集成说明](05-独立登录鉴权设计与环境切换.md)。旧账户声明已经从交接附录移除，不作为开发要求。

### 3.2 内嵌与个人/企业页签

### 3.3 公开预览游客登录

`POST /api/auth/tenant/login`，保持公共路径，无平台段。请求内容类型为 `application/json`，发送序列化后的下列对象：

```json

```

### 5.5 文件上传、元信息与访问

| 方法与公共路径 | 请求 | 成功 `data` |
| --- | --- | --- |
| `POST /api/dim3d/resource/uploadConvert` | 表单 `file`，单个模型压缩包 `.zip` | `{id,resourceName,resourceType,assetName,resourceRelativePath}` |
| `POST /api/resource/oss/upload` | 表单 `file` | `{ossId,url,fileName,originalName,fileSuffix,ext1,service}` |
| `GET /api/resource/oss/listByIds/{ids}` | 当前前端只提交单个文件编号；无正文 | 上述文件对象数组，可带 `createTime,createBy,createByName` |
| `GET /api/dim3d/resource/info/{id}` | `{id}=modelFileId` | `{id,resourceName,resourceType,assetName,resourceRelativePath}` |

模型转换只有 `code=200`、`data.id` 非空、`resourceType=MODEL` 才成功；之后把 `data.id` 作为 `modelFileId` 再提交模型表单。元信息还需非空相对路径。普通文件上传把 `ossId` 用作图片、封面或文件编号；`url` 只作当前访问地址。

模型业务 `id` → `modelFileId` → 文件元信息 → `/amm/{resourceRelativePath}`；图片业务 `id` → `iconFileId` → 文件服务解析。场景资源市场引用应持久化稳定资源编号，不保存过期签名地址。删除资源记录与回收物理文件的引用计数/延迟策略需服务端实现，不能因一个场景删引用就删除共享物理文件。

多编号分隔符、文件大小和扩展名上限、转换任务超时/失败码尚未完整冻结。现有转换上传是同步取得资源结果；若后端改为异步任务，需要新增评审并调整前端，不能直接返回新任务模型替代 `data.id`。

### 6.2 场景与修订模型

`SceneRow`：`sceneId,name,sceneDesc,sceneCategory,sceneCategoryName,sceneType,sceneTypeName,sceneKind,saveScope,publishStatus,coverAssetId,coverUrl,updateTime,tenantId,publishedPublicationId`。

`SceneDetail` 在列表字段上增加：

| 字段 | 类型 | 业务要求 |
| --- | --- | --- |
| `currentRevision` | `SceneRevision` 或无修订 | 当前编辑草稿；四包存在时必须齐全 |
| `publishedRevision` | `SceneRevision` 或无发布 | 已发布快照，不能用当前草稿冒充 |
| `accessMode` | 访问模式字符串 | 发布访问规则 |
| `accessUrl` | 字符串 | 可分享页面地址，须匹配当前部署 |
| `needPassword` | 布尔 | 是否要求密码，不返回明文密码 |

`SceneRevision`：`revisionId:string,sceneId:string,revisionNo:number,schemaVersion:number,sceneJson:string,threeDJson:string,twoDJson:string,dependenciesJson:string,contentHash?:string,baseRevisionNo?:number,changeSummary?:string,status?:number`。

`definitionJson/settingsJson` 是历史回读入口，不要求新后端再建旧方案。首次新建场景可以没有内容修订；但返回任意四包时必须四份齐全、可解析。不能用 `"{}"` 替代坏数据让用户误保存空场景。

### 6.3 编辑锁

```json
{"code":200,"msg":"操作成功","data":{"sceneId":"100001","lockToken":"仅当前会话持有的锁令牌","baseRevisionNo":1,"expireTime":"2026-10-20T12:20:00+08:00","locked":false,"lockedMap":{"100001":false}}}
```

`locked=false` 且有有效锁令牌才允许编辑保存；加锁失败或心跳 `locked=true` 表示当前不可编辑/已失锁。这里不能按字段字面误解成 `locked=true` 才获得锁。锁有效期沿用 20 分钟；前端周期心跳续期，网络中断后的租约兜底由后端负责。

锁至少绑定用户、租户、场景和页签 `clientKey`；同一用户多个页签不能共用凭证。刷新沿用该页签编号；卸载使用保持连接请求（fetch keepalive）尽力解锁，服务端仍需过期回收。解锁必须校验持有者，不得仅凭场景编号清除他人锁。

### 6.4 一次保存

```json
{
  "sceneId":"100001","lockToken":"当前锁令牌","requestId":"同一次保存重试复用的编号",
  "baseRevisionNo":1,"schemaVersion":1,
  "sceneJson":"{\"schemaVersion\":1,\"name\":\"演示场景\",\"sceneType\":\"local3d\",\"domainSlots\":{\"twoD\":\"present\",\"threeD\":\"present\"},\"metadata\":{},\"requestGlobalConfig\":{},\"publicRequests\":[],\"sceneActions\":[]}",
  "threeDJson":"{\"baseConfig\":{},\"objects\":[],\"components\":[],\"layers\":[],\"streaming\":{},\"cameraPaths\":[]}",
  "twoDJson":"{\"canvas\":{\"width\":1920,\"height\":1080},\"components\":[],\"layerTree\":[]}",
  "dependenciesJson":"{\"resources\":[],\"dataBindings\":[],\"behaviors\":[],\"deviceBindings\":[]}",
  "changeSummary":"更新二维页面"
}
```

接口模型明确要求 `sceneId`、非空 `lockToken`；前端完整保存的业务约束还要求四个非空 JSON 字符串同时发送。`requestId,baseRevisionNo,schemaVersion,changeSummary` 在来源传输类型中可选，但正式前端会生成幂等键并携带保存书签；新后端应处理，不能忽略它们。

```json
{"code":200,"msg":"保存成功","data":{"sceneId":"100001","revisionId":"200001","revisionNo":2,"lockVersion":3,"savedTime":"2026-10-20T12:00:00+08:00","conflict":false}}
```

冲突时 `data.conflict=true`、`conflictRevisionNo` 为当前书签；本地不得被覆盖。正常返回需有可供下一次保存使用的真实书签。来源描述中的版本号是当前草稿书签，不代表每次保存追加历史版本；当前编辑内容始终一份，历史发布另存。

服务端执行要求：验证身份、权限与锁 → 检查幂等键/正文摘要 → 校验四包和引用 → 同一事务整体写入草稿及书签 → 返回结果。同键同正文复用结果；同键不同正文拒绝（具体业务码待冻结）。四包任一失败必须全量回滚，不能部分覆盖。校验 `baseRevisionNo` 是严格乐观锁还是仅合理性校验，来源资料有差异，见第 12 节。

普通二维编辑混合场景时，三维包原文及三维/未知依赖必须保全；不能把当前没有三维渲染理解为三维内容为空。[四包规范](02-场景四包与数据绑定结构.md) 详细说明原文、索引与扩展字段。

### 6.5 复制、删除与权限

复制生成新场景身份和独立草稿，不复制锁、访问票据、在线会话及原发布书签。复制后的植被发布产物归属原场景，需按来源规则清理发布绑定，仅保留可编辑配置。删除需处理授权、锁、当前发布可见性和关联引用；物理资源是否级联删除由引用策略决定，不能直接删共享文件。

### 7.1 由当前内存快照另存模板

| `name` | 非空模板名称 |
| `templateType` | 当前代码 `dim3d_template_industry/dim3d_template_exhibition` |
| `category` | 对应模板类型字典编码，非空 |
| `saveScope` | `twoD/threeD/all` |
| `schemaVersion` | 当前前端发送协议版本整数 |
| `sceneJson,threeDJson,twoDJson,dependenciesJson` | 同一时刻快照的四个非空 JSON 字符串 |
| `sceneDesc,sceneCategory,coverAssetId` | 可选字符串 |
| `ownerType` | 可选 `PLATFORM/TENANT` |

**来源文档要求 `resourceBelong`，但当前 `Dim3dSceneSnapshotTemplateBody` 和组装服务没有发送它。**后端不能上线一个强制此字段而与当前调用不兼容的实现。建议按身份/`ownerType` 推导，并回填模板目录；若必须由用户选择，需明确修改前端后再冻结。

返回 `data: TemplateScene`，包含 `sceneId,sceneCode,name,sceneDesc,sceneType,sceneKind,saveScope,sceneCategory,ownerType,accessMode,coverAssetId,revisionNo,publishStatus,publishExpireTime,createBy,createByName,createTime,updateBy,updateByName,updateTime`。关键是新模板场景 `sceneId`，不能返回源场景编号。

不得要求先保存源场景再另存；未提交的当前修改也应进入模板。创建模板不修改源草稿及其保存书签。模板对象应能通过模板分页发现，返回 `templateSceneId`、`saveScope`、`sceneType`；目录资源和快照场景之间的关联需在一个业务事务内完成或提供明确失败回滚。

### 7.2 应用模板与模板创建场景

当前画布应用模板：读取 `GET /dim3d/scene/info/{templateSceneId}` → 前端裁剪/校验 → 覆盖当前编辑内存 → 下一次统一 `saveAll`。没有一个正在调用的独立“画布应用模板”接口。

二维模板按来源规则覆盖整场景并清空三维，当前已有确认提示；三维/混合模板要求场景类型一致，二维模板可跨类型但保留目标场景类型。后端仍需验证保存和另存模板的域引用，不能只信客户端裁剪。

来源真实文档另有正式模板实例化契约：`POST 业务前缀/dim3d/scene/fromTemplate`，**当前 `src/servers` 没有该请求实现**，列入后续恢复范围。

请求正文：`templateSceneId:string`、`name:string` 必填；`targetSceneType?:local3d或gis` 在二维模板时业务必填，三维/混合模板不得改变来源类型。返回普通业务封套，`data` 为新场景视图，字段与 `TemplateScene` 同族，`sceneKind=INSTANCE`，包含新 `sceneId`、保存书签和发布状态；新实例不可继承模板线上发布编号。

此服务与画布“覆盖当前编辑场景”不同：服务端新建实例场景，并按来源设计重新生成图层、对象、组件、行为和内部引用编号，在单个事务创建初始草稿；不能只改主表场景编号导致内部引用断裂。来源传输正文尚无 `requestId` 或模板修订号，重复请求幂等和源模板并发更新的冻结语义需补充。后端不能给当前页面虚构一个从未调用的已完成入口。

### 7.3 文件导入导出

当前导出从详情读取四包后由浏览器生成文件，不新增一个独立“场景导出”接口。导入校验本地四包、确认后替换编辑内存，最终仍走 `saveAll`；不需要后端解析浏览器上传的场景文件接口。不得恢复旧 `projectEngineering` 下载与保存接口。

## 8. 发布、访问解析与只读预览

### 8.1 发布生命周期

| 方法与业务路径 | 请求 | 成功 `data` |
| --- | --- | --- |
| `POST /dim3d/scene/publish/{id}` | 正文 `{accessMode:string,accessPassword?:string,changeSummary?:string}` | `PublishResult` |
| `PUT /dim3d/scene/cancel/{id}` | 无正文 | 空数据 |

`accessMode`：`PERSONAL` 仅本人、`ENTERPRISE` 企业内部、`PUBLIC_ENCRYPT` 公开加密、`PUBLIC_SHARE` 公开；具体身份可选择哪些值以权限与字典为准。公开加密要求有效密码，保存密码摘要，不回传明文。

`PublishResult`：`publishedPublicationId:string,publishNo:number,sceneRevisionId:string,revisionNo:number,status:number,publishedBy:string,publishedTime:string,alreadyPublished:boolean`。发布状态值在类型中为 `0/1/2/3`，四个值具体语义资料未完整给出，后端需冻结，不能和列表 `publishStatus` 或资源 `status` 混用。

发布先检查当前编辑内容已保存，再把四包编译为不可变快照，生成 `publicationId`。同草稿且访问设置没变化时可返回 `alreadyPublished=true`，不能重复生成无意义版本。取消发布后旧访问入口不可继续读取有效内容；历史记录是否保留与票据立即失效规则见第 12 节。

### 8.2 预览解析

`GET 业务前缀/dim3d/scenePreview/resolve?sceneId={编辑场景编号}&password={可选密码}`。

```json
{"code":200,"msg":"解析成功","data":{"resultCode":"OK","sceneId":"100001","sceneCode":"SCENE001","accessMode":"PERSONAL","tenantId":"300001","needPassword":false,"publicationId":"900001","ticket":"仅当前预览内存使用的票据"}}
```

| `resultCode` | 前端行为 |
| --- | --- |
| `OK` | 必须取得字符串发布编号与票据，再加载发布包 |
| `NOT_FOUND` | 场景不存在 |
| `NOT_PUBLISHED` | 尚未发布 |
| `EXPIRED` | 发布已过期 |
| `NEED_LOGIN` | 恢复/跳转登录，不能当匿名成功 |
| `NEED_PASSWORD` | 等待密码后重新解析 |
| `NO_PERMISSION` | 无权访问，不泄露正文 |

非成功分支元数据允许为 `null`，不要求 `publicationId/ticket`。不能用 `sceneId` 代替发布编号构造后续路径。

访问解析由现有 `scenePreviewAccess` 分流：公开探测、受限登录、游客恢复、票据取得与续期。来源旧文档称全部无用户凭证；当前个人/企业分支恢复身份后会携带凭证，个人预览已验证如此；公开分享/加密的三个包和实例依赖明确以 `anonymousPublicPreview` 走匿名运营路径。游客恢复不意味着这些公开包请求都带用户头。植被公开资源请求目前没有透传同一匿名标记，是待统一的差异。

票据沿用来源有效期 **30 分钟**，当前前端每 **20 分钟**重新调用 `resolve` 续期，无独立续票端点；续期若发布编号或访问模式改变，当前运行时拒绝混用。后端要区分模式，票据始终校验访问范围，不能对所有预览一概要求后台管理员令牌，也不能一概匿名放行。公开探测明确匿名的请求不得因无 `Authorization` 被网关统一拦截。撤销即时性和失效错误码还需联调冻结。

### 8.3 完整包与实例依赖

下表均查询参数 `ticket:string` 必填，绑定同一发布快照。

| 方法与业务路径 | 正文 | 成功 `data` |
| --- | --- | --- |
| `GET /dim3d/scenePreview/published/{publicationId}/sceneBasic` | 无 | `{publicationId,sceneId,sceneType,sceneJson:string}` |
| `GET /dim3d/scenePreview/published/{publicationId}/threeD` | 无 | `{publicationId,sceneId,sceneType,threeDJson:string}` |
| `GET /dim3d/scenePreview/published/{publicationId}/twoD` | 无 | `{publicationId,sceneId,sceneType,twoDJson:string}` |
| `POST /dim3d/scenePreview/published/{publicationId}/dependenciesByinstances` | 原始字符串数组，例如 `["400001","400002"]` | `{publicationId,items:DependencyItem[],resourceMetas?:ResourceMeta[]}` |

这是三个完整包加实例依赖接口，不要求后端实现旧的 `manifest/chunks/widgets/behaviors/assets` 多套分片端点。内部前端使用“分片”类型只是适配后模型。

`DependencyItem` 精确结构：

```json
{"instanceId":"400001","resources":["{\"resourceKey\":\"image-1\",\"assetId\":\"500001\",\"kind\":\"image\",\"owners\":[{\"domain\":\"twoD\",\"ownerType\":\"instance\",\"instanceId\":\"400001\"}]}"],"dataBindings":[],"behaviors":[],"deviceBindings":[]}
```

四类数组元素是**单条依赖的 JSON 字符串原文**，不是已解析对象，也不是把整个数组再序列化成字符串。请求体不能包装为 `{instanceIds:[…]}`，不传域字段。实例编号在同一场景跨二维、三维唯一。

`ResourceMeta`：必需稳定 `assetId:string`；其余 `kind,resourceName,resourceType,resourceFormat,assetName,resourceRelativePath,url,originalName,fileSuffix` 为可选字符串。公开图片用当前 `url`，模型用相对路径等元信息；不能让公开预览转向管理接口取文件。完整字段见附录。

后端从当前发布的依赖原文按 `owner/owners` 建索引，按需返回。初始隐藏实例的依赖可等首次显示再读取；相机移动不重新请求整个场景。前端默认每批 100 个编号；这不是后端已声明的硬上限。重复编号、缺失编号、字节上限与返回顺序资料尚未全部冻结，应明确，不能悄悄截断；当前前端可处理合法空列表但拒绝坏格式。

`POST /…/vegetation/resources?ticket=…` 为第五个发布资源数据接口，完整契约见三维专项文件。

## 9. 数据接口、媒体与残留兼容

### 9.1 场景动态数据

普通图表和控件的动态地址是用户配置的接口，不是新后台固定的“图表数据接口”。现有前端支持静态数据、历史数据集、异步网络请求（ajax）、公共请求（public），请求最多 5 组。过滤和映射由浏览器执行；后端不执行任意前端过滤脚本。

历史数据中间件的前端逻辑前缀来自 `VITE_DATA_MIDDLEWARE_PREFIX`，开发代理会去除此配置前缀。普通请求还可能被通用平台解析器改写，以下列原始服务路径和实际联调为准：

| 方法与原始路径 | 请求 | 现有响应形态 |
| --- | --- | --- |
| `GET /api/jdbcDatasource/list` | 查询 `current:number,size:number` | 当前适配器未声明行模型，待确认，不能臆造 |
| `GET /api/metadata/getColumns2` | 查询 `datasourceId:string,tableName:string` | `{code,msg,data:{url,tableName,databaseName,columns:Column[]}}` |
| `GET /api/jobJdbcDatasource/listthRecord` | 查询 `tablename:string,datasourceId:string,pageNo?:number,pageSize?:number` | `{code,msg,content:{data:对象数组,fields:string[],recordsTotal:number}}` |
| `POST /api/auth/getToken` | 正文 `username,password,rememberMe:number,messageCode?:string` | 未声明完整响应，当前无真实业务调用证据，按兼容项确认 |

`Column` 字段：`createtime,datasourceId,dbname,dbtype,fieldname,fieldtype,filedremark,id,sourcename,tablecomment,tableengine,tablename`。注意 `filedremark` 是历史拼写，不要悄悄改成其他名称；`datasourceId` 的旧声明为 `null`，`id` 为数字，后端需提供正式模型后再收敛。当前有效运行链主要读取列和表数据，不要求恢复已废弃的全局数据集持久化接口。

### 9.2 二维媒体

媒体接口为同源直达 `/api/media`，不插入平台段，不经业务请求封套。

| 方法与路径 | 请求 | 成功原始对象 |
| --- | --- | --- |
| `GET /api/media/servers` | 无正文 | `{defaultServerId:string,servers:[{id:string,name:string,address:string}]}` |
| `POST /api/media/resolve` | `{sourceUrl:string,serverId?:string,protocol?:"webrtc"或"hls"或"flv"}` | `{protocol:"webrtc"或"hls"或"flv",url:string}` |

`sourceUrl` 支持实时流传输协议（RTSP）或实时消息传输协议（RTMP）；自动接入默认浏览器实时通信（WebRTC）。网页播放器支持的流不等于 Unity 云渲染流。

现有服务实现：源地址最大 4096 字符；请求正文最大 8192 字节、读取超时 5 秒；管理服务最多 32 台；同一时刻最多 32 个不同源接入任务，重复源合并。源主机按服务端允许列表校验，散列流编号不暴露源凭据，媒体管理密钥只留服务器。上游拉流管理超时 15 秒，源流共享、无观看者回收；一个部件卸载不能关闭其他部件共享源。

错误为传输状态配合 `{message:string}`：400 参数，401 会话，403 来源或主机拒绝，408 读超时，413 过大，415 类型错误，429 过载，502 上游拉流失败，503 未配置或鉴权不可用。媒体网关当前实现仍按历史 `code=0`、`data.user.id` 校验 `MEDIA_AUTH_CHECK_URL`，这是待迁移的消费端差异，不能据此要求新登录接口返回旧结构。生产接入新鉴权前，需将网关校验同步适配本节新协议 `code=200`、`data.user.userId`；开发只允许本机，不代表生产匿名开放。

已存在 `server/mediaGateway.ts,mediaMiddleware.ts,mediaGatewayServer.ts`，后端可部署复用，也可按同契约重写。生产反向代理、媒体播放地址及跨域策略仍需配置。可选私有 RTSP 网关和浏览器会话描述协议详见三维专项文件的媒体补充，不能凭空视为当前 Java 后端已经提供。

### 9.3 残留旧接口必须单独处置

| 原始端点 | 当前证据 | 开发结论 |
| --- | --- | --- |
| `POST /admin-api/dimensions/minio/file/uploadFile/{object}` | 旧场景属性上传控件仍引用；表单字段 `uploadFile`；响应 `{code,msg,data:string}` | 后续三维属性启用前确认是否保留，或统一迁移至公共文件上传。`object` 的目录/桶语义由调用与后端确认 |

## 11. 后端开发与联调顺序

1. 按第 3.1 节完整协议实现统一业务地址下的独立认证，成功码 200；冻结运营/租户路由，不再实现旧管理初始化接口。
2. 实现字典、租户与场景管理；新建空场景可返回无当前修订，但不能伪坏数据。
3. 实现编辑锁、四包原文存取、幂等、失败事务回滚；测试锁竞争、过期与冲突。
4. 实现图片/模型/模板目录、上传解析、封面和稳定资源引用；确保重开不依赖旧签名地址。
5. 实现模板快照另存、域裁剪校验与目录关联；冻结两个已识别模板差异。
6. 实现发布与撤销、访问解析、票据、三个完整包和实例依赖；验证公开和受限四种模式。
7. 部署二维媒体及业务数据中间件；真实视频、失败恢复、共享拉流分别验收。
8. 后续三维接入地理信息与植被、云渲染控制面、信令和 Unity 协议；不以视频首帧代表全功能通过。

验收至少覆盖：字符串大编号；合法空分页；业务码/传输状态不一致；跨租户；文件上传失败不写业务表；四包原文往返；共享资源不误删；同键重试和不同正文拒绝；锁丢失；保存中断全量回滚；模板覆盖规则；发布后草稿变化不影响已发快照；取消发布/票据失效；隐藏实例首次激活；三维未运行时二维仍可用。
