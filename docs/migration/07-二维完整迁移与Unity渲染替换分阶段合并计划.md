## 1. 结论与执行边界

需求合理，两个项目采用相近的前端技术栈，来源项目也已经建立二维运行服务、命令端口和叠加层宿主端口，具备迁移基础。

实施方式确定为：以来源项目的页面、二维功能和正式数据契约为基础，替换当前项目的演示界面；保留当前项目已经实现的云渲染传输、输入编码、消息解析及 Unity 协议基础，第二阶段再接入迁移后的编辑器。不能直接覆盖整个项目，也不能只复制二维组件目录。

第一阶段必须交付可独立使用、保存、重开及预览的二维系统。它不依赖 Unity、信令服务、启动器或浏览器三维引擎。第二阶段接入云渲染后，二维内容仍由浏览器绘制，Unity 只承担三维渲染及其运行行为。

执行限制：

1. 初始编制轮次只制定计划。用户随后已授权按计划实施；当前只推进第一阶段，不部署外部服务。
2. 第一阶段包含管理页面、编辑器外壳、完整二维组件、画布、结构树、动画、事件、状态规则、交互动作、数据配置、保存、模板与二维预览，不按“最小二维演示”交付。
3. 第一阶段只建立无三维渲染的宿主及必要适配，不接入 Unity 场景加载、拾取、变换或三维联动。
4. 三维相关页面入口、配置与引用必须保留。需要实际三维能力的操作明确显示待接入，不能静默假成功。
5. 第一阶段完成后停在二维验收节点，由用户验证通过，再实施第二阶段。
6. 最终不保留当前演示页面作为正式首页，也不在浏览器中引入 Three.js、CesiumJS 作为三维兜底。
7. 来源项目保持只读。实现调整落在接收项目，不能反向改坏来源项目。

### 1.2 文中术语

- 运行时（Runtime）：执行场景加载、表现及交互的实现层。
- 端口（Port）：页面或服务依赖的能力接口，用于隔离具体引擎。
- 场景状态仓库（SceneStore）：编辑场景的领域状态。
- 命令总线（CommandBus）：统一管理命令及撤销、重做。
- 文档对象模型叠加层（DOM）：浏览器绘制的二维组件层。
- 浏览器实时通信（WebRTC）：Unity 视频和输入、业务消息的数据通道。
- 结构化远程调用（JSON-RPC）：当前 Unity 业务协议所用的请求、响应和通知方式。
- 四包：场景容器 `sceneJson`、三维内容 `threeDJson`、二维内容 `twoDJson`、依赖内容 `dependenciesJson`。
- 地理信息系统（GIS）：使用地理坐标的场景语义，不等同于某一种渲染引擎。

### 2.4 必须先解决的真实耦合

1. **画布入口耦合。** `SceneCanvas/index.vue` 同时导入旧 `renderScene`、Three 对象、Cesium 运行时及第一人称实现。保留二维叠加层不等于可以原样复制整个画布入口。
2. **预览入口耦合。** `scenePreview/index.vue` 仍导入 Three 和旧渲染实例，必须为二维验收提供独立宿主。
3. **共享出口耦合。** `scene-platform/index.ts` 统一导出具体三维运行时；`sceneRuntimeFactory.ts` 静态导入两套引擎；`viewportHost.ts` 还导入三维地图呈现协调器。只注入内存运行时，仍不足以证明构建和启动不依赖三维引擎。
4. **事件执行链耦合。** `widgetEventRuntimeService.ts` 默认动作适配器最终进入 `interactionActionExecutors.ts`，后者运行时导入 Three；`conditionRuntime.ts` 也读取旧运行时桥。必须抽离二维条件与动作，保留执行顺序、等待和取消语义。
5. **类型与状态耦合。** `types/threeScene.ts` 含 Three 类型，`sceneEditStore.ts` 混合旧三维状态和二维仓库；`dataConfig` 入口也含三维对象绑定类型。按能力拆分类型和导出，不能通过取消严格类型检查掩盖问题。
6. **命令总线不兼容。** 当前 `scene-core` 的命令总线没有来源二维适配器使用的 `recordExecuted`。不能直接将两者相连，否则首次修改可能重复应用或无法进入撤销历史。
7. **正式四包不兼容。** 来源三维包包含基础配置、对象、组件、图层、流式策略、相机路径等；容器包还有公共接口与场景动作。当前精简四包不能无损处理这些内容。
8. **管理端也包含三维实现。** 模型管理中的 `preview/RenderScene.ts` 使用 Three 解析模型。第一阶段迁移管理页时应隔离该预览入口，第二阶段评估接入 Unity 或已有服务端预览能力。
9. **构建不能整份覆盖。** 来源构建配置包含 Cesium 补丁、资源复制、开发代理及媒体中间件。只迁移二维必需部分，不复制三维构建链。
10. **验证脚本存在缺口。** 来源清单声明的 `pageFrameBrowserSmoke.mjs`、`widgetMixedGroupingBrowserSmoke.mjs` 在本次工作区未找到。实施时需补齐真实入口，不能把这些包脚本当成已经可用的验证能力。
11. **资料局部异常。** 《三维场景编辑器数据配置逻辑规范》的部分内容在显式按 UTF-8 读取后仍为乱码，且与后续更新段落混杂。实施前应核对其版本历史和现有测试；不能猜测乱码条款，也不能让早期规则覆盖后续已实现的多请求功能。

## 3. 目标结构与合并策略

### 3.1 第一阶段的工作结构

```text
来源应用入口、鉴权、路由与管理页面
  └─ 来源编辑器外壳
      ├─ 来源资源面板、结构树、属性与配置面板
      ├─ 二维画布、组件仓库、事件服务、数据调度
      ├─ 统一命令历史与正式四包保存
      └─ 无三维渲染宿主
          ├─ 提供画布尺寸、预览状态与选择协调
          └─ 三维操作明确返回尚未接入

当前 unity-runtime 保留，但不在第一阶段默认连接
```

### 3.2 第二阶段的工作结构

```text
同一套管理页面、编辑器和二维叠加层
  ├─ 二维交互及数据更新继续在浏览器执行
  ├─ 正式场景状态与唯一命令历史
  └─ Unity 三维运行时适配器
      ├─ 领域对象、动作与事件映射
      ├─ 当前 JSON-RPC 协议及传输层
      └─ 信令、实时通信、视频与输入通道
          └─ Unity 三维渲染与运行行为
```

### 3.3 状态与目录决策

- 来源 `src/scene-platform` 中引擎无关的领域模型、状态仓库和命令机制作为迁移基础，选择性迁入，避免重写已有业务。
- 来源二维仓库继续负责二维编辑态；保存时沿用 `editorSceneWidgetSnapshotAdapter.ts` 的二维片段采集及四包转换。第一阶段不额外重做二维领域模型。
- 全部可撤销操作只进入同一条命令历史。不得让现有 `scene-core` 和来源平台各维护一套正式场景状态与撤销栈。
- 当前 `scene-core` 暂留为旧 Unity 协议兼容边界；迁移后的正式页面不读取它作为第二份业务状态。第二阶段通过显式投影转换旧协议，最终收敛兼容范围。
- 对来源 `utils/renderScene` 下的纯二维工具按实际依赖选择性迁入或抽离，不能因目录名称就整包删除，也不能把旧三维渲染器整体带入。
- 引擎无关出口与具体三维实现出口分离。内存宿主不得通过统一出口、呈现器或动态扫描间接解析 Three/Cesium。
- 第二阶段保留可替换运行时边界。场景类型 `gis/local3d` 与渲染后端选择分离，不能继续按场景类型写死浏览器引擎。

### 3.5 依赖与构建适配

两个项目均使用 Vue 3.5、TypeScript 5.8、Vite 7、Pinia 3、Vue Router 4，运行环境要求也相近，优先固定来源兼容版本后迁移。

需要核对并接入的能力：

- 界面组件库、图标、样式预处理、工具类样式、分栏和拖拽：`element-plus`、`@element-plus/icons-vue`、`sass`、`tailwindcss`、`@tailwindcss/vite`、`splitpanes`、`vuedraggable`。
- 图表、通用工具和事件：`echarts`、`lodash-es`、`mitt`、`animate.css`。
- 编辑器、代码工作线程和动态图标：`monaco-editor`、`monaco-editor-vue3`、自动导入及图标构建插件；核对 `env.d.ts`、`vue.d.ts`、自动生成声明与全局 `$vue` 注册入口。
- 请求和媒体：`umi-request`、来源视频播放器实际引用的依赖，以及 `server/media*.ts` 的服务端依赖。
- 浏览器验证：按迁入脚本需要接入浏览器自动化测试依赖。不能只复制脚本而缺少浏览器、测试初始化和接口模拟。

来源依赖存在重复声明，例如前端语法扩展插件在两类依赖中版本不同。以实际构建引用为依据统一，不能原样拼接两个清单。依赖采用按需加载，特别保留图表模块化注册、组件动态加载和可重试缓存。

保留当前开发端口及输出目录，单独核对正式访问子路径、路由历史回退、字体、图标、媒体和工作线程路径。来源环境配置只提取变量定义，接收项目配置自己的业务地址、允许来源和鉴权回跳地址，不能把当前信令地址误用为业务接口地址。

### 4.1 页面范围

按来源现有路由迁移：

- 场景管理 `/sceneManage`。
- 模型管理 `/resourceManage/model`、图标图片管理 `/resourceManage/icon`、模板管理 `/resourceManage/template`。
- 编辑器 `/sceneEdit`、独立预览 `/scenePreview`。
- 种植管理 `/plantingManage` 及其既有别名。
- 管理布局、错误页、加载态、错误态、权限过期提示和相关弹窗。

管理页中的查询、筛选、分页、上传、分类与配置等业务按来源实际功能迁移。模型实时预览、三维生成结果显示、三维相机与测量等执行能力进入第二阶段，不得以保留一个按钮替代实际能力说明。种植业务接口可按既有契约保留，Unity 中的三维结果展示另行适配。

### 4.2 二维交互范围

必须核对来源已有的全部行为：

- 画布大小、适配缩放、舞台坐标、部件自身坐标、视口尺寸改变与面板分栏改变。
- 单选、多选、拖拽、尺寸调整、吸附辅助线、对齐、层级顺序、显隐、锁定、复制、删除。
- 二维视觉分组、分组嵌套、混合选中成组、真实父组件关系、子项选择与编辑。
- 属性、样式、动画配置及悬停预览；临时预览不污染保存或命令历史。
- 页面菜单、图文分页、逐条翻页、表格、测验、图片和视频等具有专用运行态的部件。
- 画布和结构树选择一致；输入框中的删除、方向键、复制等操作不能误触画布命令。

二维条件和动作沿用现有枚举与配置结构，覆盖固定值、网址参数、页面元素值、组件数据、组件运行值和当前支持的数据集值。涉及三维对象值的条件与动作保留引用，第一阶段明确不可执行，第二阶段补齐三维读取及动作端口。

### 4.3 数据管线不变量

保持现有处理次序：**获取原始值 → 执行过滤 → 标准数据集 → 字段识别 → 属性映射 → 运行时结果 → 数据预览**。

1. 请求全局配置提供默认值，当前请求覆盖；不能反向污染全局配置。
2. 公共接口以稳定编号引用，不能在每个组件复制一份配置或发起重复公共请求。
3. 多请求配置、目标字段占用、自动和人工映射标记、删除记录与持久化保持来源当前语义。
4. 组件属性配置与运行值分离；输入、分页和接口返回不能直接覆盖设计时默认值。
5. 请求切换、组件删除、场景切换、退出预览后，迟到结果必须失效，定时器和订阅必须释放。
6. 数据源、授权信息和请求转发沿用现有权限规则，不将第一方登录凭证发送到任意外部地址。
7. 来源仍有数据集相关运行及兼容代码，但 43 号设计文档排除了历史全局数据集的本期保存。迁移现有可用入口和兼容读取；不借此恢复已废弃的后端持久化方案，实施时对照当前测试明确有效范围。

### 4.4 四包无损与保存保护

这是第一阶段的硬性退出条件，不能拖到 Unity 接入后处理。

- 以来源 `sceneFourPackage.ts`、场景接口类型及 43、44 号文档为正式契约。当前 `scene-core/persistence/fourPackages.ts` 不直接用于保存来源完整场景。
- 明确二维编辑状态与正式二维包之间的转换：来源配置类、二维片段、组件正文、画布、图层树、资源归属、数据和行为依赖都需要完整往返。
- 第一阶段打开混合场景时，保存完整三维原始配置及未编辑依赖。二维操作只改二维相关内容和用户明确编辑的场景级内容，不把未实现三维能力解释为空场景。
- 合并依据依赖拥有者所属域和稳定编号，保留三维拥有者、公共接口及跨域引用；不能全量重建依赖包后遗漏三维依赖。
- 对当前转换器不认识的字段保留原始包或扩展字段。增加往返比较后再允许真实保存；不能用精简类型断言把字段静默丢弃。
- 后端仍按现有一次 `saveAll` 提交完整四包，不假设存在二维单独写接口。保留编辑锁、基准修订号、幂等键及冲突处理。
- 二维专用模板按来源规则主动清理越界引用，仅修改模板副本；正常保存混合场景不得套用该清理逻辑。
- 原始三维保全快照仅为保存兼容使用，不形成第二份可编辑领域状态，也不复制到每条撤销记录。
- 使用空场景、纯二维、混合场景、隐藏分组、多请求图表、公共接口、跨域事件及带扩展字段场景核对往返。不得在真实生产场景上试写。

### 4.5 视频与独立预览

二维视频流和 Unity 云渲染视频流分别管理，不共用连接实例、协议状态或清理函数。

来源视频部件所需的播放器和媒体中间件同步纳入迁移。需要服务器转流的协议，还依赖现有媒体服务器及生产代理；开发中间件不能替代生产服务。管理密钥留在服务端，不复制进前端环境变量或场景包。

发布预览沿用现有访问解析、票据和完整包加载规则，初始隐藏组件在首次显示后激活资源、数据与行为。第一阶段仅关闭三维运行宿主，不得绕过发布权限，也不能用编辑态数据冒充发布快照。

### 5.1 已知协议转换差异

- 来源对象标识使用领域 `id`，四包实例使用 `instanceId`；当前 Unity 模型直接使用 `instanceId`。建立稳定映射，不使用引擎对象名称或层级路径充当身份。
- 来源局部变换使用 `kind: local`、三元旋转和可为标量的缩放；当前 Unity 协议使用 `space: local`、四元数和三元缩放。需要确认旋转单位、顺序、坐标手性、轴向和单位，禁止直接强制类型转换。
- 地理坐标必须保留原始语义。Unity 是否具备对应地理能力待实际联调，不能把地理场景简单改成局部场景或删除相关配置。
- 来源模型资源常见形式与 Unity 资产包投递形式不同。已有网页模型地址不代表 Unity 可直接加载，需要确认转换、资源编号解析及产物可用性。
- 当前协议有对象创建、更新、删除和运行模式等声明，并不代表本轮已核实 Unity 对端全部实现。以能力协商与真实操作结果作为启用条件。
- 已有文档记录的编辑器直连成功和旧可执行程序版本问题，仅作为后续复核线索，本轮未重新运行 Unity 或启动器。

### 5.2 输入与生命周期

二维部件和属性面板优先处理鼠标键盘，只有底层三维视口实际获得输入时才转发 Unity。需要处理指针穿透、失焦释放、拖拽期间捕获及预览模式切换。

视频采用包含显示或填充显示时，结合实际视频区域计算坐标；黑边、画布缩放、分栏变化、设备像素比和全屏必须纳入校验。不能直接拿整个容器尺寸归一化。

会话由单一拥有者创建和关闭；控制组件、运行时及视口不得各建一个连接。场景代次和会话标识用于丢弃旧事件，输入状态、消息订阅、媒体轨道及未完成请求统一释放。

### 6.3 性能标准

- 按来源相同数据与相同浏览器环境记录二维基线，第一阶段交付性能不得明显退化；具体数量、耗时和内存以实测报告为准，不预写不存在的结果。
- 对象、部件、父子关系和分组成员以索引复用，避免每次鼠标移动重复扫描整棵树；结构改变时才更新索引。
- 拖拽与尺寸变化按动画帧合并，单次完成后提交一条历史；不得每帧完整克隆或序列化场景。
- 二维历史沿用受影响部件快照，结构操作才记录图层树，不为普通属性编辑复制全部组件。
- 保留组件按需加载、图表按需注册和可重试缓存，代码编辑器、媒体解码器不阻塞无关首屏。
- 保留统一调度和公共请求复用，卸载时取消请求、定时器、动画帧、事件监听和播放器；不增加一套组件级重复轮询。
- 第二阶段仅同步三维变化与必要运行值，不因二维编辑重发整场景；现有演示页面“新增对象后全量加载”的方式不进入正式高频链路。

每个实施批次新增或修改代码时，补齐对应中文注释，说明边界、状态所有权、取消与释放时机，避免注释与实现脱节。文件采用 UTF-8。临时脚本、临时场景导出、截图和日志在验证后清理；需要长期保留的正式测试样例及验收报告明确入库。清理前核对绝对路径，不能删除已有 `.pnpm-store/`、来源输出或用户文件。
